# board_1792401376269930700.csv

Archived on-board capture (mode 7 three-state demo, 50 MHz clock) behind the 18.28% figure.

Each row is one counter window: total_cycles (always-running reference clock cycles) and gated_cycles (processing-clock cycles actually delivered). time_s is host time.

Calculation, first 396 windows (to host time 424.074 s):

    sum(total_cycles) = 21,196,666,513
    sum(gated_cycles) = 17,322,216,584
    reduction = 1 - 17,322,216,584 / 21,196,666,513 = 18.2786 %  (reported as 18.28 %)

This is one specific interval. It differs from the 17.62 % session figure shown by the page and from the 18.8 % RTL simulation and 18.66 % offline model results. Rows after 396 are kept in the file but are not used for the 18.28 % figure.

Reproduce:

    python3 -c "import csv;r=list(csv.DictReader(open('board_1792401376269930700.csv')))[:396];T=sum(int(x['total_cycles']) for x in r);G=sum(int(x['gated_cycles']) for x in r);print(len(r),T,G,round((1-G/T)*100,4))"

From the repository root, run:

    python board/counters/calc_18_28.py

The CSV contains 437 records. Only records 1 through 396 contribute to the
published 18.28% interval. This measures processing-clock activity reduction,
not measured board-power savings. The raw CSV is preserved without changes.
